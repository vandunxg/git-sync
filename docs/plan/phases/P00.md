# P00 - Reconnaissance and decision ledger

Outcome: Resolve actual repository/toolchain context and record missing evidence without fabrication.

Phase dependencies: none. Task dependencies are in TASKS.json.

## Entry criteria

Read the source ledger, relevant rules and contracts. Inspect the actual repo and completed dependency evidence. Do not infer readiness from a verbal status alone.

## Tasks

### P00-T01 - Inspect repository and current instructions

Inventory actual code, existing instructions, dependencies and test commands; do not scaffold over an existing app.

**Requirements:** REQ-02, REQ-37
**Acceptance scenarios:** TEST-TEMPLATE, TEST-NO-FAKES
**Permitted paths:** `README.md`, `AGENTS.md`, `state/TOOLCHAIN.json`, `state/IMPLEMENTATION.json`

**Done evidence:** actual changed files, executed command results, task-specific assertions, review record, and screenshots/remote observations where applicable. Paths are an upper boundary, not permission to refactor unrelated modules.

## Verification and exit gate

Use the applicable `core`, `frontend`, `visual`, `security` or `native` quality profile plus the task-specific tests. A profile pass does not replace tests listed above. Provide a handoff describing exact invariants, unresolved blockers and the next ready task. Do not skip dependencies or mark a phase done before its tasks pass.

## Failure / rollback

Stop only the affected task. Revert app changes by a reviewed source diff when appropriate; never undo a remote write blindly. For uncertain GitLab outcomes use observation/reconciliation. Preserve previous verified mirrors, snapshots and user workspace data. Keep failed evidence and do not rewrite it as success.

P00 may complete while a visual export is still unavailable, provided that blocker is recorded. Final visual freeze belongs to P02-T01. This allows backend phases P03-P07 to proceed independently of Figma access.

## Validation-kind clarification

TASKS.json distinguishes inspection, design_review and implementation. P00 inspections and P02 reference/review tasks use executed inspection or actual human review evidence; their linked product acceptance scenarios remain NOT_RUN until an implementation task executes them. No empty application suite is allowed to stand in for inspection or visual approval.
